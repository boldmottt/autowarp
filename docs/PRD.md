# AutoWarp PRD

시편 사진을 **실물 규격 그대로** 펴서 아카이브에 쌓고 인쇄·평가에 바로 쓰는 이미지로 만드는 도구.

- 문서 버전: **v0.2 (2026-11-12) — 8문항 답변 반영, 범위 확정**
- 코드 버전: v0.2.0
- 이전: v0.1 (초안, 확인 필요 8문항)

---

## 0. 확정된 답변 (v0.1 8장 → v0.2 반영)

| 질문 | 답변 | 결정 |
|---|---|---|
| Q1 촬영 방식 | 책상 위가 기본, 손에 들고 찍는 경우 가끔 | 손각도 같은 원근 변환으로 처리. 별도 기능 없음. 검출 실패 시 **수동 4점**이 안전망(P0) |
| Q2 규격 | 90% 이상 170×70, 가끔 비규격 | **프리셋 + 직접 입력** 둘 다 P0. 170×70 기본값 |
| Q3 색 판단에 쓰나 | **아카이브용으로 사용** | **색 정규화 기능 전체 제외**(F-30~F-33 폐기). 대신 규격 통일·재현성·원본 보존이 최우선 |
| Q4 코드 자동 인식 | 아니오 | **F-40(OCR) 삭제** |
| Q5 아카이브 연동 | 고민 중 | **P2 보류.** 대신 나중에 붙이기 쉽게 출력 파일명·이력 CSV 규칙을 지금 고정 |
| Q6 TIFF | 필요할 수도 있음 | **P1 확정 → 구현 완료** (LZW 무손실, dpi 유지) |
| Q7 처리량 | 20~50장 | 병렬 처리 불필요. 실측 **장당 58ms**(4000×3000) → 50장 3초 |
| Q8 회전 | 모름 | **수동 회전(P1) 먼저**, 자동 판정은 실사용 로그를 보고 판단 |

**"아카이브용"의 의미를 기준으로 잡았다.**
결과물은 한 번 만들면 계속 쌓이는 자산이므로, 이 도구의 성공 기준은 "예쁘게 펴졌다"가 아니라 아래 세 가지다.

1. **규격이 같다** — 언제 뽑아도 같은 픽셀 크기(170×70mm → 2008×827px). 나중에 다시 열어도 같은 조건.
2. **원본이 남는다** — 원본은 절대 수정하지 않고, 결과는 새 파일로만 만든다.
3. **재현된다** — 같은 원본·같은 규격이면 결과가 항상 동일해야 한다(해시 비교로 검증).

## 1. 문제와 목표

시편을 책상 위에 놓고 위에서 찍으면 네 가지가 걸린다.

1. **비스듬하다** — 모서리가 사각형이 아니게 찍혀 그대로 자르면 패턴이 늘어난다.
2. **크기가 제각각** — 사진마다 픽셀 크기가 달라 나란히 비교할 수 없다.
3. **양이 많다** — 20~50장을 한 장씩 포토샵에서 변형하면 반나절이 사라진다.
4. **실패가 섞인다** — 한 장이 안 풀린다고 전체가 멈추면 안 된다.

목표는 하나다. **폴더를 던지면 3분 안에 아카이브에 넣을 수 있는 규격 이미지 묶음이 나온다.**

### 비목표

- 포토샵 대체(레이어·마스크·리터칭) 아님
- 3D 스캔·형상 측정 아님
- **색 보정·화이트밸런스 아님** (Q3: 아카이브용)
- 클라우드 동기화·모바일 앱 아님

## 2. 기능 요구사항 (확정)

우선순위: **P0 = 없으면 못 씀 / P1 = 두 배 편해짐 / P2 = 보류**

### 2.1 규격과 출력

| ID | 요구사항 | P | 상태 | 수용 기준 |
|---|---|---|---|---|
| F-01 | mm + dpi → 출력 픽셀 계산 | P0 | 완료 | 170×70@300 = **2008×827** |
| F-02 | 버림이 아닌 **반올림** | P0 | 완료 | 170mm→2008, 70mm→827 (테스트 고정) |
| F-03 | dpi 메타데이터 기록 | P0 | 완료 | PNG pHYs / JPEG·TIFF dpi. 다시 열면 300 |
| F-04 | **규격 프리셋** | P0 | 완료 | `170x70`, `85x35`, `210x297` + 직접 입력 |
| F-05 | 출력 포맷 PNG/JPEG/TIFF | P1 | 완료 | TIFF 는 LZW, dpi 유지 |
| F-06 | 비율 유지 옵션 | P2 | 완료 | 켜면 늘어나지 않고 여백 발생 |

## 3. 사용 흐름

```
촬영       책상 위, 위에서 (가끔 손에 들고)
   ↓
일괄 처리   autowarp batch 사진/ 출력/ --preset 170x70 --fail-dir 실패/ --log 이력.csv
   ↓
확인       결과 폴더 훑기. `!` 표시된 것과 실패 폴더만 다시 본다
   ↓
수동 보정   GUI 로 열어 점 조정(또는 회전) 후 저장
   ↓
아카이브    규격 통일된 원본 이미지로 축적
```

## 5. 데이터 규칙 (고정)

**출력 파일명**

```
<원본이름>_<가로>mm<세로>mm_<가로>px<세로>px.<ext>
M-01120_170x70mm_2008x827px.png
```

패턴 지정: `--pattern "시편_{n:03d}_{w}x{h}mm"` → `시편_001_170x70mm.png`

**폴더**

```
사진/        촬영 원본 (절대 수정하지 않음)
출력/        규격 변환 결과 (덮어쓰기 금지, 중복 시 _2)
실패/        검출 실패 사본 (수동 처리용)
이력.csv     시각, 원본, 출력, 규격, dpi, 픽셀, 회전, 비율차이, 결과, 비고
```

## 8. 남은 확인 (2개만)

**Q5. 아카이브 연동을 할 것인가?**
지금은 결과를 폴더에 쌓는 방식. 연동하면 "처리 → 아카이브 등록"이 한 번에 끝나지만, 두 앱의 폴더 규칙을 맞춰야 한다.
→ 쌓인 폴더를 나중에 직접 등록하는 것으로 충분한가?

**Q8. 회전이 틀린 채로 나오는 빈도**
v0.2 는 수동 회전(CLI `--rotate`)만 있다. 실사용 이력 CSV 의 `회전` 열을 보면 실제로 얼마나 필요한지 판단할 수 있다.
→ 20~30장 돌려본 뒤 알려주면 자동 판정(F-42)을 넣을지 결정.

## 9. 검증

1. **합성 회귀 테스트 29개** — 규격 픽셀, 검출 정확도, dpi 태그, 한글 경로, 배치 실패 격리, 회전, 덮어쓰기, CSV.
2. **실사 골든셋(예정)** — 실제 시편 사진 20장으로 검출 성공률·처리 시간·육안 판정 기록. 사진은 저장소에 올리지 않는다.
3. **재현성** — 같은 원본·같은 규격이면 결과 해시가 동일.
