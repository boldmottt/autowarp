# AutoWarp PRD

시편 사진을 **실물 규격 그대로** 펴서 인쇄·평가에 바로 쓰는 이미지로 만드는 도구.

- 문서 버전: v0.1 (2026-11-12)
- 현재 코드: v0.1.0 (엔진 + CLI + GUI 골격)
- 이 문서의 목적: **기능 범위를 확정하기 전에 검토용으로 돌리는 초안.** 아래 8장 "확인 필요"에 답을 주면 v0.2 로 확정한다.

---

## 1. 배경과 문제

시편(specimen)은 책상 위에 놓고 위에서 찍는다. 손으로 들고 찍거나, 시편이 커서 몸을 뒤로 빼거나, 조명이 한쪽에서 들이치면 결과물이 이렇게 된다.

1. **비스듬하다** — 네 모서리가 사각형이 아니라 마름모·사다리꼴이 된다. 그대로 자르면 패턴이 늘어나 보인다.
2. **크기가 제각각이다** — 같은 170×70mm 시편인데 사진마다 픽셀 크기가 다르다. 나란히 붙여 비교할 수 없다.
3. **양이 많다** — 한 번에 수십 장을 찍는다. 한 장씩 포토샵에서 변형하면 반나절이 사라진다.
4. **색이 흔들린다** — 조명 때문에 같은 컬러인데 사진마다 밝기·색온도가 다르다. 컬러매칭 판단에 쓰려면 기준이 필요하다.

AutoWarp 는 이 네 가지를 없애는 것이 목적이다.

## 2. 목표 / 비목표

### 목표

- 사진 한 장 → **규격 픽셀 크기의 평면 이미지**가 3초 안에 나온다.
- 폴더 하나를 던지면 **전량 자동 처리**되고, 실패한 것만 목록으로 알려준다.
- 결과물은 **실물 크기(mm)와 해상도(dpi)가 파일에 기록**되어 인쇄·비교에 바로 쓸 수 있다.
- 사람이 손대는 것은 **예외 처리뿐**이다(자동 검출 실패, 방향이 뒤집힌 경우).

### 비목표 (이번 범위 아님)

- 포토샵 대체가 아니다. 레이어·마스크·리터칭 없음.
- 3D 스캔·형상 측정 없음. 두께·곡면은 다루지 않는다.
- 클라우드 동기화·다중 사용자 협업 없음.
- 모바일 앱 없음(촬영은 휴대폰, 처리는 데스크톱 전제).

## 3. 사용자와 흐름

주 사용자: 시편을 직접 촬영하고 컬러·패턴을 평가하는 담당자 1인.

```
촬영      책상 위에 시편을 놓고 위에서 촬영 (한 컷에 1~N개)
   ↓
보정      AutoWarp: 검출 → 원근 보정 → 규격 픽셀 변환 → dpi 저장
   ↓
확인      결과 폴더를 훑어보고 실패·기울기 이상만 다시 처리
   ↓
활용      인쇄 비교 / 제안서 삽입 / 아카이브 등록
```

핵심 시나리오 3개:

- **S1 (단건 정밀)**: 평가용 대표 시편 1장. GUI 로 열고, 자동 검출된 네 점을 눈으로 확인하고, 필요하면 점을 끌어 미세 조정한 뒤 저장.
- **S2 (대량)**: 촬영 40장을 폴더에 넣고 CLI 한 줄. 2분 뒤 결과 폴더와 실패 목록을 받는다.
- **S3 (재현)**: 지난달에 만든 결과와 같은 규격으로 다시 뽑는다. 규격 프리셋을 골라 같은 픽셀 크기를 얻는다.

## 4. 기능 요구사항

우선순위: **P0 = 없으면 못 씀 / P1 = 업무가 두 배 편해짐 / P2 = 있으면 좋음**

### 4.1 규격과 출력

| ID | 요구사항 | 우선순위 | 수용 기준 |
|---|---|---|---|
| F-01 | 실물 크기(mm) + dpi 로 출력 픽셀을 계산한다 | P0 | `170×70mm @300dpi = 2008×827px`. 1px 오차 없음 |
| F-02 | 계산된 픽셀은 **반올림**한다(버림 금지) | P0 | 170mm→2008, 70mm→827. 테스트로 고정 |
| F-03 | 결과 파일에 dpi 메타데이터를 기록한다 | P0 | PNG `pHYs`, JPEG/TIFF dpi 태그. 다시 열면 300dpi 로 읽힘 |
| F-04 | 규격 프리셋을 저장·선택한다 | P1 | 최소 `170×70`, `85×35`, 사용자 추가 프리셋 |
| F-05 | 출력 포맷 선택 (PNG / JPEG / TIFF) | P1 | TIFF 는 LZW 무손실 |
| F-06 | 규격 대비 원본 비율 유지 옵션 | P2 | 켜면 늘어나지 않고 여백이 생긴다 |

### 4.2 검출과 변환

| ID | 요구사항 | 우선순위 | 수용 기준 |
|---|---|---|---|
| F-10 | 사진에서 시편 네 모서리를 자동 검출한다 | P0 | 실제 시편 사진 20장 중 16장 이상 자동 성공 |
| F-11 | 사진 테두리(프레임)를 시편으로 오인하지 않는다 | P0 | 면적 95% 초과 후보 제외. 회귀 테스트 있음 |
| F-12 | 한 사진에 여러 시편이 있으면 각각 검출한다 | P1 | 2개 배치 사진에서 2개 모두 검출 |
| F-13 | 검출 결과를 마우스로 끌어 미세 조정한다 | P0 | 점 이동이 실시간 반영 |
| F-14 | 검출 실패 시 수동으로 네 점을 찍을 수 있다 | P0 | 실패해도 작업이 막히지 않는다 |
| F-15 | 90도 단위 회전을 자동 판정한다 | P1 | 가로/세로가 뒤집힌 시편을 바로 세운다 |
| F-16 | 가장자리 선에 스냅해 1px 단위로 붙인다 | P2 | 점이 시편 경계선에 달라붙는다 |

### 4.3 대량 처리

| ID | 요구사항 | 우선순위 | 수용 기준 |
|---|---|---|---|
| F-20 | 폴더 단위 일괄 처리 (CLI) | P0 | 40장 2분 이내, 장당 평균 2초 이하 |
| F-21 | 실패 사진은 건너뛰고 목록으로 보고한다 | P0 | 중간에 멈추지 않는다. 실패 목록 출력 |
| F-22 | 파일명 규칙을 지정한다 | P0 | 기본 `<원본>_170x70mm_2008x827px.png`, 패턴 지정 가능 |
| F-23 | 미리보기(dry-run) | P1 | 파일을 쓰지 않고 예정 목록만 출력 |
| F-24 | 하위 폴더까지 재귀 처리 | P2 | 폴더 구조를 유지한 채 출력 |

### 4.4 색과 품질 (검토 필요)

| ID | 요구사항 | 우선순위 | 수용 기준 |

| F-31 | 밝기 정규화(같은 조명 조건으로 통일) | P1? | 같은 시편 2회 촬영 시 평균 밝기 차 3% 이내 |

## 6. 데이터 규칙

**출력 파일명**

```
<원본이름>_<가로>mm<세로>mm_<가로>px<세로>px.<ext>
M-01120_촬영_170x70mm_2008x827px.png
```

패턴 지정 시: `시편_{n:03d}_{w}x{h}mm.png` → `시편_001_170x70mm.png`

**폴더**

```
원본/         촬영 원본 (건드리지 않음)
출력/         규격 변환 결과 (덮어쓰기 금지, 같은 이름이면 _2 붙임)
실패/         검출 실패 사본 (수동 처리용)
처리이력.csv  원본, 출력, 규격, dpi, 시각, 결과
```

## 7. 비기능 요구사항

| 항목 | 기준 |
|---|---|
| 처리 속도 | 4000×3000px 사진 1장 2초 이내 |
| 정확도 | 합성 이미지 꼭짓점 오차 3px 이내, 출력 픽셀 오차 0 |

## 8. 확인 필요 (여기가 핵심)

아래 답에 따라 P1/P2 항목이 확정되거나 빠진다. 각 항목에 **현재 가정**을 적어 두었다.

**Q1. 실제 촬영 방식은?**
가정: 책상 위, 위에서 촬영, 한 컷에 시편 1개(가끔 여러 개).
→ 손에 들고 찍거나, 시편이 커서 비스듬히 찍히는 경우가 많은가?

**Q2. 규격은 170×70mm 하나인가?**
가정: 주력은 170×70, 가끔 85×35(A4 반).
→ 다른 규격(정사각, 소형 컬러칩, A4 전체)도 자주 쓰는가?

**Q3. 이 도구를 **색 판단**에 쓰는가?**
가정: 지금은 모양·크기 통일이 목적. 색은 별도로 본다.
→ 같은 컬러를 여러 번 찍어 나란히 비교할 일이 있는가? 있다면 F-30(화이트밸런스)·F-31(밝기 정규화)이 P0 로 올라간다.

**Q4. 파일명에 시편 코드를 자동으로 넣을 필요가 있는가?**
가정: 지금은 원본 파일명을 그대로 이어받는다.
→ 사진 안에 코드가 인쇄되어 있고 그걸 읽어 파일명으로 쓰고 싶은가? (OCR 붙이면 P1)

**Q5. 결과물을 어디로 보내는가?**
가정: 폴더에 쌓고 필요할 때 꺼내 쓴다.
→ 아카이브 앱에 바로 등록하고 싶은가? (연동하면 P1)

**Q6. TIFF 가 필요한가?**
가정: PNG 로 충분.
→ 포토샵/일러스트로 넘길 때 TIFF·CMYK 가 필요한가?

**Q7. 하루에 몇 장을 처리하는가?**
가정: 한 번에 20~50장.
→ 100장 이상이면 병렬 처리(P2)를 P1 로 올린다.

**Q8. 방향(회전)이 틀린 채로 나오는 경우가 잦은가?**
가정: 가끔 있다.
→ 잦으면 F-15 를 P0 로 올린다.

## 10. 검증 방법

1. **합성 이미지 회귀 테스트** (현재 16개): 규격 픽셀, 검출 정확도, dpi 태그, 한글 경로, 배치 실패 격리.
2. **실사 골든셋**: 실제 시편 사진 20장을 저장소 밖에 두고, 검출 성공률·처리 시간·육안 판정을 기록. (사진은 저장소에 올리지 않는다)
3. **재현성**: 같은 원본·같은 규격이면 결과 픽셀이 항상 동일해야 한다(해시 비교).
